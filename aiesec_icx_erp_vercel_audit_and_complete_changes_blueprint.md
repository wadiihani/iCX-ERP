## 1. Executive Diagnostic Summary: The 6 Root Structural Flaws in the Current ERP Build

> **Transparency Note on Live URL Inspection**: Automated crawler requests to `https://icx-erp.vercel.app/` are blocked by Vercel's client-side SPA / bot protection layer. This audit combines the exact UI/UX issues you reported on the live deployment (Sidebar navigation vs. redundant Dashboard CTA buttons, missing KPIs, and lack of modular structure) with a complete line-by-line code audit of the ERP application attached in your workspace (`aiesec_rabat_icx_erp.html`). Every single function, DOM ID, form input, chart, and data table has been inspected below.

| Root Flaw ID | What Is Currently Wrong in the App | Operational Impact for AIESEC in Rabat | Required Architectural Change |
| :--- | :--- | :--- | :--- |
| **`ROOT-01`** | **Dashboard Has Redundant Navigation Call-to-Actions (`CTAs`) Instead of Clickable KPI Cards** | Because you already have a Sidebar for navigation, the `"360° Stakeholder Database Completeness"` list (`switchTab(...)` buttons) and `"Manage All EPs →"` links on the Dashboard are redundant, while real KPIs (Conversion Rates, Velocity, Quotas, Member Engagement) are completely absent. | Remove all navigation CTA buttons from the Dashboard. Replace the 6 static counter boxes with **9 Clickable Domain KPI Cards (`3×3 Grid`)** that open an **In-Place Expanded KPI Scorecard & Graph Panel** right inside the Dashboard when clicked. |
| **`ROOT-02`** | **Append-Only ("Create-Only") UI — Zero Edit, Update, Delete/Archive, or Exception Flows** | Once you create a Partner, Contact, Opportunity, EP, IR Partner, Host Family, or Case, **you cannot edit any field**! Worse, you can only click `"Advance Stage →"` forward—there is **no way to mark a B2B Deal `CLOSED_LOST` or mark an EP `REJECTED`, `WITHDRAWN`, `APPROVAL_BROKEN`, or `REALIZATION_BROKEN`**. | Add a **Slide-Over Record Inspector & Edit Drawer** for every entity (`Edit Fields`, `Upload Proof PDF`, `Change Owner`, `Archive`) and add dedicated **Exception / Break / Rejection Modals** enforcing `AEPP` feedback and `Annex 2` replacement rules. |
| **`ROOT-03`** | **Concatenated Text Strings Instead of Relational Foreign Keys & Typed Fields** | Critical data is squashed into single text inputs: `epFullName` combines Name + EXPA ID; `epContact` combines Email + Phone; `epPassport` combines Passport # + Expiry Date; `epArrival` combines Date + Airport + Flight #; `epAccommBuddy` combines Hostel + Bed + Buddy; `irQuotas` is a string `"20 APP / 8 APD / 8 RE"`. | Split every concatenated string into **typed atomic fields** (`DATE`, `TIME`, `NUMBER`, `EMAIL`, `TEL`) and **Relational Foreign-Key Dropdowns** (`orgId`, `irEntityId`, `bedId`, `memberId`) so KPIs, bed occupancy, and SLA countdowns compute automatically. |
| **`ROOT-04`** | **Fake / Hardcoded Math in Dashboard Charts & KPI Subtitles** | In `renderDashboardCharts()`, the Funnel Chart adds hardcoded numbers (`db.eps.length + 3` for Applied, `db.eps.length + 1` for Shortlisted), and KPI subtitles (`"Avg Resp: 5.0h"`, `"100% Dahir / ICE Tracked"`, `"Rabat 14-Day Lock Active"`) are static hardcoded text that never updates when data changes! | Replace all hardcoded strings and `+ 3` math with **live aggregation functions** driven by actual timestamps (`appliedAt`, `firstContactedAt`, `acceptedAt`, `approvedAt`, `realizedAt`) and `statusHistoryLogs`. |
| **`ROOT-05`** | **Giant 9-Tab Monolithic Intake Modal & Permanent Top Launchpad Clutter** | A permanent 8-button `"Universal Stakeholder Data Entry Bar"` banner sits at the top of `<main>` on every tab, and clicking `+ Put Stakeholder Data` opens a massive 9-tab modal where unrelated entities (Host Families + Pickups, or Finance + Team Members) share the exact same generic 6-field form. | Delete the permanent 8-button top banner. Give each module its own contextual **`+ New [Entity]` Slide-Over Drawer** with dedicated schemas (separating Housing from Pickups, Sponsors from Cases, and Finance from Team Members). |
| **`ROOT-06`** | **No Dedicated Member Engagement, Attendance Tier & Team Standards (`TeSt`) Module** | Team members are stored as 3 rows inside `db.financeAndTeam` where `amountOrRole` holds `"12000"` for money or `"LCVP_ICX"` for a person! There is zero tracking of whether members are engaged, their attendance tiers (`Tier 1 Core` to `Tier 4 Drop-Off`), `O2O` completion, or `Team Standards (TeSt)`. | Split **Module 8 (AFPM Finance)** and **Module 9 (Member Engagement, Attendance Tiers, O2Os & Team Standards)** into separate Sidebar modules with full People Analytics. |
