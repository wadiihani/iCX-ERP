# Plan 00-01: Core Schema DDL, Enums & Relational Tables (M0)

## Objective
Establish the foundational PostgreSQL database schema for the iCX Data Integrity & Tracking System, defining the core enumerated types, relational tables, and foreign key constraints specified in `iCX_Data_Integrity_Tracking_Spec.md` §3.

## User Persona & Role
Backend Architect & Database Engineer

## Specialized Skills
`supabase`, `supabase-postgres-best-practices`

## Scope
1. Enums:
   - `programme`: `'GV', 'GTa', 'GTe'`
   - `flow_stage`: `'attraction', 'consideration', 'preparation', 'experience', 'post_experience'`
   - `ex_status`: `'APL', 'ACP', 'APD', 'RE', 'FI', 'CO', 'REJECTED', 'WITHDRAWN'`
   - `break_type`: `'APD', 'RE', 'FI', 'CO'`
2. Core Tables:
   - `member`: `id (uuid)`, `name`, `role`, `active (boolean)`, `team_id`, `created_at`
   - `entity_org`: `id (uuid)`, `name`, `kind`, `country`, `is_frozen (boolean)`, `frozen_since (timestamptz)`
   - `op_partner`: `id (uuid)`, `name`, `type`, `city`, `expa_org_id`, `owner_id (FK member)`, `stage`, `last_touchpoint_at`
   - `opportunity`: `id (uuid)`, `op_id`, `programme`, `expa_opp_id`, `slots`, `duration_weeks`, `hours_per_week`, `benefits`, `accommodation_provided`
   - `contract`: `id (uuid)`, `opportunity_id (FK)`, `signed_at`, `payment_terms`, `key_deadlines`, `document_id`
   - `ep`: `id (uuid)`, `expa_ep_id (unique)`, `full_name`, `home_entity_id (FK)`, `contact (restricted JSON)`, `owner_id (FK)`
   - `exchange`: `id (uuid)`, `ep_id (FK)`, `opportunity_id (FK)`, `programme`, `status`, `break_type`, `approved_at`, `re_date`, `fi_date`, `co_date`, `owner_id (FK)`, `expa_hash`, `expa_synced_at`, `deleted_at`, `deleted_reason`, `created_at`
   - `status_history`: `id (bigserial)`, `exchange_id (FK)`, `from_status`, `to_status`, `break_type`, `at`, `by_member (FK)`, `source`, `reason`, `proof_id`
   - `audit_log`: `id (bigserial)`, `ts`, `actor (uuid)`, `action`, `table_name`, `record_id`, `before (jsonb)`, `after (jsonb)`, `request_id`
   - `rule_registry`: `key`, `value (jsonb)`, `effective_from`, `effective_to`, `source`, `note`

## Verification
- Validate schema migration files compile cleanly without SQL syntax errors.
- Confirm all foreign keys and non-null constraints enforce data relational integrity.
