# Plan 00-02: Database Integrity Triggers & Append-Only Guarantees (M0)

## Objective
Implement PostgreSQL triggers and constraint functions enforcing the non-negotiable integrity invariants (INV-01, INV-02, INV-05, INV-09) defined in `iCX_Data_Integrity_Tracking_Spec.md` §2 and §3.3.

## User Persona & Role
Database Reliability Engineer & Security Architect

## Specialized Skills
`supabase`, `supabase-postgres-best-practices`

## Scope
1. **Trigger 1 (INV-01 Hard-Delete Block)**:
   - `BEFORE DELETE` trigger on all business tables (`op_partner`, `opportunity`, `contract`, `ep`, `exchange`, etc.).
   - Raises exception and logs `DQ-081` attempt when physical `DELETE` is executed.
2. **Trigger 2 (INV-02 Append-Only History)**:
   - `BEFORE UPDATE OR DELETE` trigger on `status_history` and `audit_log`.
   - Raises exception unconditionally to guarantee immutability.
3. **Trigger 3 (INV-05 EP Voice Immutability)**:
   - `BEFORE UPDATE` trigger on `standard_check`.
   - Rejects any modification to `ep_reported_answer` or `ep_reported_at` once initially recorded.
4. **Trigger 4 (INV-09 Universal Audit Logger)**:
   - `AFTER INSERT OR UPDATE` trigger across all domain tables.
   - Automatically populates `audit_log` with timestamp, actor ID, action type, table name, record ID, and JSON before/after snapshots.
5. **Trigger 5 (DQ-080 Status Transition Sync)**:
   - `AFTER UPDATE OF status` on `exchange`.
   - Ensures corresponding `status_history` entry is created; rejects status mutation if history record is missing.

## Verification
- Test T-01: Attempting `DELETE` fails with custom SQL exception and logs attempt.
- Test T-02: Manual `UPDATE` on `status_history` fails.
- Test T-03: Updating `ep_reported_answer` once set is rejected.
