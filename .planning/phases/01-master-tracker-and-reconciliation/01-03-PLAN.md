# Plan 01-03: EXPA CSV/JSON Sync & Reconciliation Engine (M1)

## Objective
Implement the authoritative EXPA synchronization pipeline, enforcing the >5% row-drop quarantine guard (DQ-082, Acceptance Test T-04), idempotent status and date reconciliation (DQ-040, DQ-041, DQ-042, Acceptance Test T-05), inactive owner detection (DQ-011, Acceptance Test T-06), and tamper-evident `import_batch` tracking with SHA-256 integrity hashes.

## User Persona & Role
Integration Architect & Reliability Engineer

## Specialized Skills
`xlsx`, `supabase-postgres-best-practices`

## Scope
1. **`import_batch` Schema & State Tracker**:
   - Stores `source`, `file_sha256`, `rows_in`, `rows_ok`, `rows_rejected`, `schema_version`, `status` (`applied`, `quarantined`, `failed`), `quarantine_reason`, and timestamps.
2. **Schema Drift Validator**:
   - Inspects CSV headers against the canonical EXPA export contract (`expa_ep_id`, `full_name`, `status`, `opportunity_id`, `approved_at`, `re_date`, `fi_date`, `co_date`).
   - Rejects corrupted or drift-affected payloads prior to ingestion.
3. **>5% Row-Drop Quarantine Guard (DQ-082, Acceptance Test T-04)**:
   - Compares incoming batch row count against previous successful batch.
   - If row count dropped > `import.max_row_drop_pct` (default 5% from `rule_registry`), the batch is quarantined, zero mutations are committed, and a `DQ-082` Blocker issue is logged.
4. **Idempotent Reconciliation Engine (INV-04, Acceptance Test T-05)**:
   - EXPA is the single source of truth for statuses and dates.
   - If EXPA status differs from Tracker status (`DQ-040`), tracker updates status with `source = 'expa_sync'`, creates append-only `status_history` record, and auto-resolves `DQ-040`.
   - Tracker-owned fields (`tracked_status`, proofs, cases) are never touched by EXPA sync.
   - Missing rows in EXPA are preserved and flagged with `DQ-042` (never hard-deleted, INV-01).
5. **Inactive Owner Detection (DQ-011, Acceptance Test T-06)**:
   - Detects records owned by deactivated members and raises `DQ-011` Blocker issue triggering handoff workflow.

## Verification
- Comprehensive test suite in `tests/expa-sync-reconciliation.test.ts` verifying:
  - T-04: Batch quarantine on >5% row drop (DQ-082).
  - T-05: Status reconciliation where EXPA wins, logs `expa_sync`, and auto-resolves DQ-040.
  - T-06: Deactivated owner detection raising DQ-011.
  - SHA-256 batch integrity and schema drift rejection.
