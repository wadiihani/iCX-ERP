# Plan 01-02: Stage Required-Field Validator Gates (M1)

## Objective
Implement strict stage validation gates preventing premature customer flow stage advancement and enforcing the §5.1 "No Empty Records" matrix, §4.2 Transition Guards (including INV-07 ICB frozen entity block), and automated DQ-020 issue generation.

## User Persona & Role
QA Lead & Operations Process Architect

## Specialized Skills
`supabase-postgres-best-practices`, `data-table-engine`

## Scope
1. **Stage Required Field Matrix Validator (`src/lib/data-integrity/stage-gates.ts`)**:
   - `Attraction`: Mandatory partner info (`name`, `type`, `city`, `contact_person`, `channel`, `expa_org_id`, `owner_id`).
   - `Consideration`: Mandatory opportunity parameters (`title`, `programme`, `slots`, `duration`, `hours/week`, `benefits`, `accommodation`) + EP dossier (`expa_ep_id`, `name`, `home_entity_id`, `contact`).
   - `Preparation` (APD): Mandatory signed contract (`signed_at`, `payment_terms`, `key_deadlines`, `document_id`), exchange dates (`approved_at`, `re_date`), 16 standards rows created.
   - `Experience` (RE): Mandatory finish date (`fi_date`), review milestones.
   - `Post-Experience` (CO): Mandatory survey/debrief outcome; system-only confirmation via EP survey import (S1).
2. **Transition Guards (§4.2)**:
   - Hard Guard: `entity.is_frozen = false` (INV-07). Blocks approval/realization if home entity is frozen.
   - Hard Guard: `FI -> CO` blocked if initiated manually by AIESEC (must come via EP survey import).
   - Soft Guard: APD $\rightarrow$ RE warns if visa docs not delivered or preparation standards (#4, #5, #7, #8) untracked.
3. **Data Quality Rule DQ-020**:
   - Generates structured `DQ-020` issues for missing stage fields (Warn in-stage; Blocker at transition).
4. **Integration with `exchangeService`**:
   - Gated status transitions with bypass support for `source = 'expa_sync'` (INV-04).

## Verification
- Comprehensive test suite in `tests/stage-gates.test.ts` verifying:
  - Acceptance of complete records across all 5 stages.
  - Rejection of transitions with missing required fields (DQ-020).
  - Hard blocking of approvals for frozen home entities (INV-07, T-11).
  - Hard blocking of manual FI $\rightarrow$ CO transitions without EP survey confirmation.
  - EXPA sync bypass preserving EXPA authority (INV-04).
