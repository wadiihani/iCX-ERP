## Task Specification

### 1. Problem
Tasks and reminders are scattered across disparate pages (stale sales deals, unanswered IR messages, unverified visa packs, missing accommodation confirmations, overdue invoices). Without a centralized task engine, critical operational SLAs slip unnoticed.

### 2. AIESEC Process & Source Basis
- AIESEC Hub Operating Model §5.12: Unified task engine where every module generates tasks through the same contract (type, related record, owner, creator, due date, priority, status, completion evidence, escalation path).
- Timestamps and deadlines must be evaluated in local operational timezone (`Africa/Casablanca`).
- Idempotency keys must prevent duplicate task creation on automated runs.

### 3. Current Implementation Confirmed in Code
- Basic workload tracker in `/admin` with manual tasks.
- No automated cross-module queue ingestion or idempotency protection.

### 4. Desired Behaviour
1. **Unified Task Engine**:
   - Single task ingestion pipeline collecting actionable items from:
     - Partner follow-ups & stale deals (>7d without update)
     - Unanswered IR messages or unconfirmed supply
     - Incomplete contract signatures or missing opportunity fields
     - EP document verification & selection actions
     - Visa verification & pre-arrival readiness checklists
     - Upcoming arrivals (<3d) lacking pickup confirmation
     - Incomplete Exchange Standards (#10a/#10b) & open corrective actions
     - Overdue invoices (>14d overdue)
   - Every task has: `id`, `type`, `title`, `sourceModule`, `relatedRecordId`, `ownerId`, `dueDate`, `priority` (`CRITICAL`, `HIGH`, `MEDIUM`, `LOW`), `status` (`OPEN`, `IN_PROGRESS`, `COMPLETED`, `ESCALATED`), `idempotencyKey`.
2. **Idempotent Automation Runner**:
   - Background/scheduled evaluators use deterministic `idempotencyKey` (e.g. `task_visa_${epId}_${deadline}`) to guarantee that re-running never creates duplicate tasks.
   - Evaluated in `Africa/Casablanca` timezone.
3. **Operational Workload View**:
   - Sortable, filterable task queue with one-click navigation to the source record.
   - Quick "Complete with Evidence" action modal.

### 5. Data Model & API Changes
- Standardize `UnifiedTask`:
  - `id`: UUID, `idempotencyKey`: string (unique index), `type`: string, `title`: string, `sourceModule`: string, `relatedRecordId`: string, `ownerUserId`: string, `dueAt`: string, `priority`: string, `status`: string, `completedAt`: string | null, `evidenceUrl`: string | null.
- Create `src/lib/tasks/unified-task-engine.ts` with automated rule evaluators.

### 6. Permission & Privacy Impact
- Members see tasks assigned to them; Team Leaders and LCVPs see team-wide queues.

### 7. Acceptance Tests
- `tests/workload-handoffs.test.ts` & `tests/sla-automations-and-calendar.test.ts`:
  - Verifies task generation across modules.
  - Verifies idempotency (second evaluation does not insert duplicate task).
  - Verifies Casablanca timezone date-math calculation.

### 8. Migration & Rollback Plan
- Pure additive schema and task engine; no impact on existing records.

### 9. Completion Evidence
- Vitest passing 100% on task engine and idempotency test assertions.
