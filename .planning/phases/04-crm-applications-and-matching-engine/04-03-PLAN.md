# Plan 04-03: Matching Engine, Dual-Status Decoupling & Svelte 5 Operations Views

## Objective
Build the matching completion engine with Acceptance Note document uploads, Sending Entity (SE) payment proof verification, the dual-status decoupling state machine (Official EXPA status vs Local Operational Readiness), and rich Svelte 5 user interfaces for candidate management, Kanban screening, and bulk imports.

## Scope
1. **Acceptance Note & SE Payment Verification**:
   - `acceptance_notes` table: UUID, application_id, ep_signature_date, partner_signature_date, document_url, verified_by, verification_status (`PENDING`, `VERIFIED`, `REJECTED`).
   - `se_payment_proofs` table: UUID, application_id, sending_entity_id, payment_reference, amount_eur, proof_document_url, verified_by, status (`PENDING`, `VERIFIED`).
2. **Dual-Status State Machine (Decoupling Invariant)**:
   - Enforces the core invariant from master spec:
     - **Official EXPA Status**: `APP` &rarr; `ACC` &rarr; `APD` &rarr; `RE` &rarr; `FI` &rarr; `CO`.
     - **Local Operational Readiness**: `DRAFT` &rarr; `READY` &rarr; `AT_RISK` &rarr; `BLOCKED` &rarr; `DONE`.
   - Local operational tasks (pre-arrival visa, flight confirmation, housing booking) determine readiness independently of EXPA approval.
   - Upon `ACCEPTED` stage, system validates signed Acceptance Note and reserves capacity slot.
   - Upon `APPROVED` stage, verifies both EXPA `APD` status and local readiness checks before clearing match for operational exchange spawning.
3. **Frontend Views (Svelte 5 Runes)**:
   - `apps/web/src/routes/(app)/crm/+page.svelte`:
     - EP directory table with search, country filters, masked phone/passport toggles, and document viewer.
     - Bulk CSV/XLSX import modal with column mapping and dry-run preview table.
   - `apps/web/src/routes/(app)/applications/+page.svelte`:
     - 9-stage Kanban board and high-density tabular view with SLA badges (`On Track`, `Due Soon`, `Overdue`).
     - Application drawer showing EP summary, OP interview notes, screening score, and Acceptance Note upload.
     - Dual-status visual widget showing official EXPA progress vs local operational readiness.
4. **REST Endpoints**:
   - `POST /api/v1/applications/{id}/acceptance-note`: upload and verify Acceptance Note.
   - `POST /api/v1/applications/{id}/se-payment`: submit and verify Sending Entity payment proof.
   - `POST /api/v1/applications/{id}/match-approve`: finalize match approval with slot commitment.

## Dependencies
- Phase 4-01 & 4-02 backend components.
- Phase 3 slot reservation logic.

## Verification Criteria
- Automated pytest tests in `services/api/tests/test_matching_dual_status.py`:
  - Dual status state transitions remain decoupled.
  - Acceptance note and SE payment proof validations are enforced prior to match approval.
- Frontend build passes `npm --prefix apps/web run build` with zero TypeScript or Svelte rune warnings.
