# Plan 04-02: 9-Stage Application Screening Engine, SLA Clocks & OP Interview Portal

## Objective
Implement the 9-stage screening workflow for incoming applications (`Applied → Contacted → Screening → Shortlisted → Sent to OP → Interview → OP Decision → Accepted → Approved`), SLA deadline tracking (24-48h first contact, 3-day OP review), and the Opportunity Provider (OP) candidate forwarding and interview feedback recording interface.

## Scope
1. **Database Schema & Migrations**:
   - `applications` table: UUID, ep_id, opportunity_id, slot_id, current_stage (9 stages), official_expa_status, operational_readiness, assigned_manager_id, first_contact_deadline, op_feedback_deadline, applied_at, last_contacted_at, notes.
   - `application_screenings` table: UUID, application_id, reviewer_id, language_proficiency, background_check_passed, cultural_fit_rating (1-5), skills_match_rating (1-5), motivation_notes, recommendation (`RECOMMENDED`, `NEUTRAL`, `REJECTED`).
   - `op_interviews` table: UUID, application_id, scheduled_at, interviewer_name, interview_type (`ONLINE`, `IN_PERSON`), questions_asked, op_decision (`ACCEPTED`, `REJECTED`, `SECOND_ROUND`), feedback_notes.
2. **Deterministic Screening State Machine**:
   - Strictly validates state transitions across the 9 stages:
     `APPLIED` &rarr; `CONTACTED` &rarr; `SCREENING` &rarr; `SHORTLISTED` &rarr; `SENT_TO_OP` &rarr; `INTERVIEW` &rarr; `OP_DECISION` &rarr; `ACCEPTED` &rarr; `APPROVED`.
   - Handles rejection transitions (`REJECTED`) and candidate withdrawal (`WITHDRAWN`) with reason tracking.
3. **Operational SLA Timer Calculations**:
   - Computes SLA deadlines upon entry into specific stages:
     - `APPLIED` &rarr; first contact deadline = `applied_at + 48 hours`.
     - `SENT_TO_OP` &rarr; OP feedback deadline = `sent_at + 72 hours`.
   - Flags applications as `SLA_BREACHED` if current time exceeds deadline without progression.
4. **OP Candidate Forwarding & Portal Endpoint**:
   - Endpoint to prepare sanitized candidate packet for sending to Opportunity Provider (anonymized/masked if required).
   - Endpoint to log OP interview notes, rating, and hiring decision.
5. **REST Endpoints**:
   - `GET /api/v1/applications`: list applications with filters (stage, opportunity_id, SLA status).
   - `POST /api/v1/applications`: create application linking EP to Opportunity slot.
   - `POST /api/v1/applications/{id}/transition`: advance or regress stage with validation.
   - `POST /api/v1/applications/{id}/screening`: record internal screening evaluation.
   - `POST /api/v1/applications/{id}/op-forward`: record forwarding to OP.
   - `POST /api/v1/applications/{id}/op-interview`: record OP interview feedback and hiring decision.

## Dependencies
- Phase 3 Opportunity & Slot models.
- Phase 4-01 EP models.

## Verification Criteria
- Automated pytest tests in `services/api/tests/test_applications_screening.py`:
  - 9-stage sequence validates valid and invalid stage jumps.
  - SLA timer correctly flags overdue contact or OP review.
  - OP interview recording correctly transitions state to `OP_DECISION` and `ACCEPTED`.
