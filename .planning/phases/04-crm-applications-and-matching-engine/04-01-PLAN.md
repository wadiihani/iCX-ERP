# Plan 04-01: EP Domain, PII Masking, Document Storage & Bulk Ingestion

## Objective
Establish the Exchange Participant (EP) candidate data layer with strict privacy protections (PII masking based on RBAC permissions), secure CV/document metadata management, duplicate detection algorithms, and a robust CSV/XLSX bulk import parser with dry-run validation.

## Scope
1. **Database Schema & Migrations**:
   - `exchange_participants` table: UUID, expa_person_id, first_name, last_name, email, phone (masked for restricted roles), country_of_residence, nationality, home_mc, home_lc, date_of_birth, gender, passport_number (masked), cv_url, status, tags.
   - `ep_documents` table: UUID, ep_id, doc_type (`CV`, `PASSPORT_COPY`, `LANGUAGE_CERT`, `STUDENT_PROOF`, `ACCEPTANCE_NOTE`), file_name, file_size_bytes, mime_type, storage_path, uploaded_by, expires_at, created_at.
2. **PII Masking & Privacy Service**:
   - Deterministic PII masking: Mask passport numbers (e.g. `******1234`), phone numbers (e.g. `+212 *** *** 44`), and email addresses for non-authorized roles (`GUEST`, unauthorized member) unless user has `ep:read_pii` permission.
   - Secure signed URL generator utility for private document retrieval.
3. **Duplicate Detection Engine**:
   - Fuzzy and exact duplicate detection based on `email`, `expa_person_id`, and composite `first_name + last_name + nationality`.
4. **CSV/XLSX Bulk Import Engine**:
   - Parse legacy spreadsheets and EXPA export CSVs/XLSXs.
   - Dry-run validation returning errors, warnings, and valid candidate count before committing to database.
   - Column auto-mapping for standard EXPA export headers (`Person ID`, `First Name`, `Last Name`, `Email`, `Country`, etc.).
5. **REST Endpoints**:
   - `GET /api/v1/crm/eps`: list EPs with dynamic PII masking based on actor role.
   - `POST /api/v1/crm/eps`: create EP candidate.
   - `GET /api/v1/crm/eps/{id}`: retrieve EP candidate profile with documents.
   - `POST /api/v1/crm/eps/import/dry-run`: upload CSV/XLSX and return validation report.
   - `POST /api/v1/crm/eps/import/execute`: commit validated import batch.

## Dependencies
- Phase 1 Foundation & RBAC (`ep:read_pii`, `ep:create`, `ep:write`).
- Python `openpyxl` or standard CSV parser for spreadsheet processing.

## Verification Criteria
- Automated pytest tests in `services/api/tests/test_crm_eps.py`:
  - Verify PII masking when requested by user without `ep:read_pii` vs full unmasked access for `ADMIN`/`VP_ICX`.
  - Duplicate detection correctly flags existing email or expa_person_id.
  - CSV bulk import dry-run identifies invalid rows and executes clean batch commit.
