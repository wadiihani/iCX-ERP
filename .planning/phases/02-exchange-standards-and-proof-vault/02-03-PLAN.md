# Plan 02-03: Proof Document Vault & Dead Link Detection (M2)

## Objective
Implement the tamper-evident Proof Document Vault managing verifiable evidence for exchange standards (#4–#15), status change governance, and quality cases, enforcing SHA-256 hash verification, Google Drive link integrity, dead link / checksum drift detection (DQ-083), and executing Acceptance Test T-20.

## User Persona & Role
Standards & Quality Lead & Internal Control Board (ICB) Auditor

## Specialized Skills
`supabase-postgres-best-practices`, `emil-design-eng`, `ui-styling`

## Scope
1. **Migration (`supabase/migrations/20261102000005_icx_proof_vault_v1.sql`)**:
   - Table `proof_document`:
     - `id`: uuid primary key.
     - `file_name`: text not null.
     - `mime_type`: text not null.
     - `file_size_bytes`: bigint not null.
     - `drive_url`: text not null (Google Drive link format validated).
     - `sha256_hash`: text not null (64-character hex checksum).
     - `uploaded_by`: uuid not null references member(id) (INV-03, INV-09).
     - `uploaded_at`: timestamptz not null default now().
     - `last_verified_at`: timestamptz.
     - `verification_status`: 'verified' | 'dead_link' | 'checksum_mismatch' | 'unverified'.
     - `metadata`: jsonb.
     - `deleted_at`, `deleted_reason`: soft delete columns (INV-01).
   - Foreign key reference constraints and triggers (`fn_icx_prevent_hard_delete` and `fn_icx_universal_audit_log`).
2. **TypeScript Types (`src/lib/types/data-integrity.ts`)**:
   - `ProofDocument`, `ProofVerificationStatus`, `ProofVerificationResult`.
3. **Proof Vault Service (`src/lib/data-integrity/proof-vault.ts`)**:
   - `registerProofDocument()`: Registers evidence with SHA-256 checksum, valid URL, and actor attribution.
   - `verifyProofIntegrity()`: Validates URL accessibility and content hash match.
   - `runNightlyDeadLinkScan()`: Automated nightly integrity scanner detecting dead links (HTTP 404/inaccessible) and mutated payloads, raising `DQ-083` warnings with 7-day resolution SLAs.
   - `attachProofToStandard()`: Links proof to `standard_check` (transitioning `is_unproven` to proven).
4. **Acceptance Test Harness (`tests/proof-vault-integrity.test.ts`)**:
   - **T-20**: Given a Drive proof link that returns 404, then DQ-083 flags it within one nightly run.
   - Verification of tamper detection (checksum mismatch).
   - Amber unproven clearance upon valid proof linkage.
   - INV-01 prevention of hard delete on proof documents.
