# Plan 14-01: Contract to Opportunity to Multi-Slot Relational Normalization & Wave Manager

## Objective
Implement Section 4 (`CHG-20`, `CHG-23`) of `aiesec_icx_erp_vercel_audit_and_complete_changes_blueprint.md`: normalize `db.contractsAndOpps` into `db.contracts` (1) → `db.opportunities` (N) → `db.opportunitySlots` (N), build the multi-slot wave manager, and compute real-time dynamic capacity metrics from linked EPs.

## Execution Skills
- `vercel-composition-patterns`
- `supabase-postgres-best-practices`
- `ui-ux-pro-max`

## Detailed Tasks
1. Normalize Opportunity & Slot schemas in `src/lib/types/database.ts` & `src/lib/opportunity/opportunity-machine.ts`:
   - `Contract`: `id`, `orgId`, `mouNumber`, `signedDate`, `expiryDate`, `mouDocumentUrl`, `termsAndConditions`.
   - `Opportunity`: `id`, `contractId`, `orgId`, `title`, `product` (`iGV`, `iGTa`, `iGTe`), `portfolioProject` or `jobField`, `durationWeeks`, `salaryMad`, `epFeeMad`, `modality` (`PHYSICAL`, `PARTLY_REMOTE`), `openingsTotal`, `supervisorContactId`.
   - `OpportunitySlot`: `id`, `oppId`, `waveLabel` (`Wave 1 — Winter 26`, `Wave 2 — Summer 26`), `startDate`, `endDate`, `capacity`, `appliedCount`, `acceptedCount`, `approvedCount`, `realizedCount`, `completedCount`.
2. Build Multi-Slot Wave Manager in `src/components/opportunity/slot-wave-manager.tsx`:
   - Display slot timeline bands per opportunity with dates and open capacity (`Available = capacity - approvedCount`).
   - `+ Add Slot Wave` button allowing multiple intake dates per Opportunity.
3. Replace static counts with dynamic aggregation:
   - Compute `appliedCount`, `acceptedCount`, `approvedCount`, `realizedCount`, and `completedCount` by querying linked EPs where `ep.oppId === op.id` and `ep.slotId === slot.id`.

## Verification
- Unit test in `tests/opportunity-and-slots.test.ts` verifying relational hierarchy and live count aggregation from EP status changes.
