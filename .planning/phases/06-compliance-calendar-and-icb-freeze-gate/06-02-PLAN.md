# Plan 06-02: ICB Freeze Gate Authority & Unfreezing Workflow (INV-07, D10, T-11)

## 1. Context & Objectives
- **Phase**: M6 — Compliance Calendar & ICB Freeze Gate
- **Spec Reference**: `iCX_Data_Integrity_Tracking_Spec.md` §11.2 (Freeze logic), §12.4 (Role privileges), D10 (Freeze Authority), INV-07 (Frozen Entity Gate), §16 (Acceptance Test T-11).
- **Core Requirements**:
  1. **Freeze Authority (D10)**:
     - `entity.is_frozen` can ONLY be toggled by `LCVP iGV` (or ECB with explicit ICB reference).
     - Mandatory ICB audit reference link / justification required when setting frozen.
  2. **INV-07 Enforcement Gate (Acceptance Test T-11)**:
     - "Given entity is_frozen, when a user tries to process an approval, then blocked with ICB reference."
     - Blocks any stage gate advancement (e.g. APL/ACP -> APD, or signing contracts) for exchanges linked to the frozen entity.
  3. **Unfreezing Workflow**:
     - `unfreezing_submission` compliance item tracking corrective actions, audit clearance evidence, and formal sign-off before unfreezing.
  4. **System Invariants**:
     - Universal audit log (INV-09) records actor and ICB audit source link.

## 2. Deliverables
1. Implementation in `src/lib/data-integrity/compliance-calendar.ts` and stage-gates integration.
2. Vitest test suite in `tests/compliance-calendar.test.ts` covering Acceptance Test T-11 and D10 freeze authority.
