# Plan 13-02: 8-Stage Deal Stepper, BANT Discovery Gate & Contract Gate

## Objective
Implement Section 3 (`CHG-15`, `CHG-16`) of `aiesec_icx_erp_vercel_audit_and_complete_changes_blueprint.md`: replace linear stage advancement with an 8-stage stepper, add `CLOSED_LOST` / `DISQUALIFIED` flows with mandatory loss reasons, and enforce discovery and contract gates.

## Execution Skills
- `vercel-composition-patterns`
- `ask-sonner`
- `ui-styling`

## Detailed Tasks
1. Refactor B2B Deal pipeline state machine in `src/lib/sales/pipeline-machine.ts`:
   - Stages: `NEW_LEAD` → `CONTACTED` → `MEETING_SCHEDULED` → `DISCOVERY_COMPLETED` → `PROPOSAL_SENT` → `NEGOTIATION` → `CONTRACT_SIGNED` → `ONBOARDED_LIVE`.
   - Terminal states: `CLOSED_LOST`, `DISQUALIFIED`.
   - Transitions allow direct stage selection or moving backward with confirmation.
   - Enforce mandatory `lossReason` (`Budget`, `No Supervisor`, `Housing`, `Unresponsive`, `Legal Mismatch`, `Other`) when moving to `CLOSED_LOST` / `DISQUALIFIED`.
2. Build Stage Progression Gates:
   - **Discovery / BANT Gate**: Block moving to `PROPOSAL_SENT` unless structured discovery fields are completed:
     - `Diagnosed Need`, `Target Product`, `Headcount`, `Supervisor Full-Time Check`, `Workspace Verified`, `Fee Capacity`.
   - **Contract Gate**: Block moving to `CONTRACT_SIGNED` or `ONBOARDED_LIVE` unless a linked contract in `db.contracts` is attached with proof link/file.
3. Build `src/components/sales/deal-status-modal.tsx`:
   - Interactive dialog for selecting new stage, entering loss reason, or fulfilling missing gate requirements.

## Verification
- Unit test in `tests/b2b-deal-pipeline.test.ts` verifying discovery gate blocks proposal without BANT fields and contract gate blocks signing.
