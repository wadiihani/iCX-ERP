# Plan 09-02: Docker Containerization, Security Hardening & Production Packaging

## Goal
Containerize the entire iCX Command Center multi-service architecture using production-grade Docker and Docker Compose (PostgreSQL 16 with pgvector, Redis, Temporal, FastAPI API, and SvelteKit Web), enforce and verify security hardening policies (strict RBAC authorization checks, role-based PII masking, and tamper-resistant audit logs), and deliver operational documentation and release runbooks.

## User Requirements Addressed
- Multi-container Docker deployment (`docker-compose.yml`) for `postgres`, `redis`, `temporal`, `api`, `web`
- Security hardening:
  - Role-Based Access Control (RBAC) denial enforcement for unauthorized actors
  - PII masking on EP sensitive credentials (passports, phones)
  - Tamper-resistant audit logging on all consequential state transitions
- Production documentation and release runbooks in `docs/OPERATIONS_RUNBOOK.md` and updated `README.md`

## Detailed Tasks

### Task 1: Production Containerization
- `services/api/Dockerfile`: Multi-stage Python build with non-root security user (`appuser`), curl healthchecks on `/health`, and production uvicorn server.
- `apps/web/Dockerfile`: Multi-stage Node 20 alpine build with SvelteKit production build, non-root user, and node runner.
- `docker-compose.yml`: Comprehensive orchestration:
  - `postgres` (with healthcheck and persistent volume `postgres_data`)
  - `redis` (with healthcheck and persistent volume `redis_data`)
  - `temporal` (Temporal auto-setup orchestration)
  - `api` (FastAPI backend dependent on healthy postgres/redis/temporal)
  - `web` (SvelteKit frontend dependent on api)
- `.dockerignore` files for clean build contexts.

### Task 2: Security Hardening & Audit Verification
- `services/api/tests/test_security_hardening.py`:
  - RBAC checks: unauthorized roles receive 403 Forbidden on critical routes (e.g. member attempting match approval, completion approval, fee waiver, or gated EXPA mutation dispatch).
  - PII masking: candidate passport numbers and phone numbers masked for accounts without `ep:pii:view`.
  - Audit logging: state mutations create immutable `audit_logs` records.

### Task 3: Operations Runbook & Release Documentation
- `docs/OPERATIONS_RUNBOOK.md`: Complete operations runbook covering setup, seeding, disaster recovery, environment variables, and EXPA sync operations.
- Update `README.md` with complete project architecture, quickstart commands, and compliance reference.

### Task 4: Full Suite Verification & Sign-Off
- Run full pytest test suite (including all module tests, master journeys, and security hardening).
- Run full SvelteKit production build (`npm run build`).
- Update GSD roadmap and state to 100% completion.
