# Plan 03-02: Statutory Request Checklist Validators & Timing Engine (M3)

## Objective
Implement statutory validation rules and cutoff timing engines for all status request types (§7.1–§7.4), enforcing strict checklist completeness, APIP clause references, English PDF proof mandates, timing rules (`early_fi` T-08, `extension_fi` T-09), direct break pathing for aged APD records (T-10), and blocking submissions with missing items (T-07, DQ-057).

## User Persona & Role
Customer Experience Lead & ECB Case Analyst

## Specialized Skills
`supabase-postgres-best-practices`, `emil-design-eng`, `ui-styling`

## Scope
1. **Statutory Checklist Validators (`src/lib/data-integrity/status-validators.ts`)**:
   - `validateEarlyFiRequest()`:
     - `ep_in_required_status`: EP status must be 'realized' (RE).
     - `proof_lc2lc_email_pdf`: LC2LC email proof attached (T-07).
     - `proof_ep_opp_agreement`: EP-opportunity agreement proof attached.
     - `timing_ok`: `submitted_at <= desired_new_finish - 7 days` (read from `rule_registry: early_fi.request_min_days_before_new_finish`; T-08).
     - `duration_min_ok`: New duration >= programme minimum (`gv.duration_weeks = 4`).
     - `single_ep`: Single EP isolation (INV-06).
   - `validateExtensionFiRequest()`:
     - Same proof/reason structure.
     - `timing_ok`: `submitted_at <= opportunity_finish - 14 days` (read from `rule_registry: extension_fi.request_min_days_before_finish`; T-09).
   - `validateBreakRequest()`:
     - `ep_same_status`: EP status equals break stage (`break_apd` requires APD, `break_re` requires RE, etc.).
     - `proof_lc2lc_email_pdf_en`: English LC2LC PDF required.
     - `proof_ecb2ecb_email_pdf_en`: English ECB2ECB PDF required.
   - `checkApdRePassedDirectBreak()`:
     - APD past `re_date`: creates urgent `DQ-052` issue ("fake status risk — Violation L5").
     - GV past `re_date + 20 days`: enables direct extraordinary break without proof requirement (T-10).
2. **Submission Gate Integration (`src/lib/data-integrity/status-governance.ts`)**:
   - Gating `transitionLifecycle(id, 'ready' | 'submitted')` with statutory checklist validation.
   - Raising `DQ-057` blocker issue when checklist or cutoff conditions are violated.
3. **Acceptance Test Suite (`tests/status-request-validators.test.ts`)**:
   - **T-07**: Early FI missing LC2LC PDF is blocked with missing item named.
   - **T-08**: Early FI desired finish in 5 days fails timing check (`timing_ok = false`).
   - **T-09**: Extension with finish in 10 days fails timing check (`timing_ok = false`).
   - **T-10**: APD whose `re_date` passed 21 days ago raises urgent DQ-052 and direct break path is offered without proof.
