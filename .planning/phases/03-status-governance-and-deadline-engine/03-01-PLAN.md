# Plan 03-01: Status Request Schema & Lifecycle State Machine (M3)

## Objective
Implement the `status_request` governance schema and finite state machine for managing exchange status changes across all six statutory kinds (`early_fi`, `extension_fi`, `break_apd`, `break_re`, `break_fi`, `break_co`), strictly enforcing single-EP isolation (INV-06), mandatory owner attribution (INV-03, INV-09), soft deletion guarantees (INV-01), and lifecycle state progression (`draft` → `ready` → `submitted` → `approved` | `rejected` → `applied_in_expa`).

## User Persona & Role
Customer Experience Lead & LCVP iGV / ECB Auditor

## Specialized Skills
`supabase-postgres-best-practices`, `emil-design-eng`, `ui-styling`

## Scope
1. **Migration (`supabase/migrations/20261102000006_icx_status_request_v1.sql`)**:
   - Table `status_request`:
     - `id`: uuid primary key default gen_random_uuid().
     - `exchange_id`: uuid not null references exchange(id) on delete restrict.
     - `ep_id`: uuid not null references ep(id) on delete restrict (INV-06).
     - `kind`: text check in ('early_fi', 'extension_fi', 'break_apd', 'break_re', 'break_fi', 'break_co').
     - `current_status`: text check in ('draft', 'ready', 'submitted', 'approved', 'rejected', 'applied_in_expa').
     - `desired_date`: date (e.g., new finish date).
     - `reason`: text not null.
     - `apip_clause_ref`: text (statutory APIP reference clause).
     - `ticket_ref`: text (Zendesk / national ticketing reference, mandatory at 'submitted').
     - `checklist_state`: jsonb not null default '{}'::jsonb.
     - `evidence_proof_ids`: jsonb not null default '[]'::jsonb.
     - `owner_id`: uuid not null references member(id) on delete restrict (INV-03).
     - `created_at`, `submitted_at`, `decided_at`, `applied_at`: timestamptz.
     - `rejection_reason`: text.
     - `deleted_at`, `deleted_reason`: soft delete columns (INV-01).
   - B-tree indexes on `exchange_id`, `ep_id`, `kind`, `current_status`, `owner_id`.
   - Triggers: `trg_prevent_delete_status_request` (INV-01) and `trg_audit_status_request` (INV-09).
2. **TypeScript Types (`src/lib/types/data-integrity.ts`)**:
   - `StatusRequestKind`, `StatusRequestLifecycle`, `StatusRequest`.
3. **Status Governance Service (`src/lib/data-integrity/status-governance.ts`)**:
   - `createStatusRequest()`: Validates single EP per request (INV-06), active owner (INV-03), exchange correspondence.
   - `transitionLifecycle()`:
     - Enforces state machine paths: `draft` → `ready` → `submitted` → `approved` | `rejected` → `applied_in_expa`.
     - Blocks transition to `submitted` if `ticket_ref` is omitted.
     - Records attribution, transition timestamps, and rejection details.
   - `softDeleteStatusRequest()`: Enforces INV-01 soft delete with audit trail.
4. **Verification Test Harness (`tests/status-governance-lifecycle.test.ts`)**:
   - Validates all 6 request kinds.
   - Enforces single EP per ticket invariant (INV-06).
   - Validates state machine forward/backward guard transitions.
   - Enforces required `ticket_ref` on submit.
   - Prohibits physical hard deletes (INV-01).
