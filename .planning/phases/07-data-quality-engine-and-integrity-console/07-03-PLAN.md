# Plan 07-03: Integrity Console Engine & 15 Views (§14)

## 1. Context & Objectives
- **Phase**: M7 — Data Quality Engine & Integrity Console
- **Spec Reference**: `iCX_Data_Integrity_Tracking_Spec.md` §14 (Integrity Console, Dashboards).
- **Core Requirements**:
  1. **15 Statutory Console Views (§14 Matrix)**:
     - 1. **Data Health Score**: 0–100 weighted score + grade + sub-scores.
     - 2. **Open DQ Issues**: Count grouped by severity × owner.
     - 3. **Staleness**: % records past SLA by stage.
     - 4. **Completeness Heatmap**: % complete per required field × stage.
     - 5. **Reconciliation**: Mismatch count per sync (DQ-040..DQ-042).
     - 6. **Orphans List**: Records without active owner (drill to handoff).
     - 7. **Deadline Radar**: Next 14 days by deadline type with countdown.
     - 8. **Request Queue**: Breaks, FI, extensions by state and age (Kanban).
     - 9. **Standards Delivery**: `std_delivery_pct` per standard # and per IR partner.
     - 10. **Standards Mismatch**: DQ-055 count (tracked vs EP-reported).
     - 11. **Partner Health**: Days since touchpoint, NPS readiness, open standards.
     - 12. **IR Clusters**: 2×2 matrix scatter data (`upscale`/`grow`/`understand`/`invest`).
     - 13. **Funnel Analytics**: Call→Open, Open→APL, APL→APD, process times.
     - 14. **Quality Cases**: CS Minimums KPIs (resolution time, compensation, recurrence).
     - 15. **Sync Log & Handoffs**: Batch import logs and pending handoffs.
  2. **Filtering & Drill-Down**:
     - Global filter support: owner, programme (GV, GTa, GTe), stage, date range, partner, IR partner.
