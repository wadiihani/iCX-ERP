# 08-02-PLAN: Isolated EXPA Sync Adapter, Reconciliation Console & Gated Mutation Handler

## Objective
Implement an isolated, fault-tolerant EXPA/GIS synchronization adapter that stages external records into local staging tables, identifies dual-status discrepancies without overwriting local operational readiness, provides an interactive Reconciliation Console UI (`/expa`), and strictly enforces human sign-off before dispatching outbound mutations to EXPA.

## Proposed Changes

### 1. Database Schema Additions (`database/migrations/008_temporal_and_expa_schema.sql`)
- `expa_sync_runs`:
  - `id` (UUID PK)
  - `sync_mode` (VARCHAR) - `POLLING`, `WEBHOOK`, `MANUAL_RECONCILIATION`
  - `status` (VARCHAR) - `RUNNING`, `SUCCESS`, `PARTIAL_FAILURE`, `FAILED`
  - `records_scanned` (INTEGER DEFAULT 0)
  - `records_staged` (INTEGER DEFAULT 0)
  - `conflicts_detected` (INTEGER DEFAULT 0)
  - `error_message` (TEXT)
  - `started_at`, `completed_at`
- `expa_staged_records`:
  - `id` (UUID PK)
  - `sync_run_id` (UUID FK -> `expa_sync_runs`)
  - `entity_type` (VARCHAR) - `OPPORTUNITY`, `APPLICATION`, `EP_PROFILE`
  - `expa_id` (VARCHAR)
  - `raw_payload` (JSONB)
  - `status` (VARCHAR) - `STAGED`, `RECONCILED`, `CONFLICT_DETECTED`, `IGNORED`
  - `created_at`
- `expa_reconciliation_records`:
  - `id` (UUID PK)
  - `staged_record_id` (UUID FK -> `expa_staged_records`)
  - `entity_type` (VARCHAR)
  - `local_entity_id` (UUID NULLABLE)
  - `field_name` (VARCHAR) - e.g. `status`, `start_date`, `compensation`
  - `local_value` (VARCHAR)
  - `expa_value` (VARCHAR)
  - `discrepancy_type` (VARCHAR) - `STATUS_MISMATCH`, `DATE_MISMATCH`, `UNLINKED_EP`, `MISSING_LOCAL_RECORD`
  - `resolution_status` (VARCHAR) - `PENDING`, `LOCAL_KEPT`, `EXPA_ACCEPTED`, `MANUAL_OVERRIDE`
  - `resolved_by_user_id` (UUID NULLABLE)
  - `resolution_notes` (TEXT)
  - `created_at`, `resolved_at`
- `expa_gated_mutations`:
  - `id` (UUID PK)
  - `entity_type` (VARCHAR)
  - `local_entity_id` (UUID)
  - `expa_id` (VARCHAR)
  - `target_action` (VARCHAR) - `ACCEPT_APPLICATION`, `APPROVE_APPLICATION`, `UPDATE_DATES`
  - `mutation_payload` (JSONB)
  - `status` (VARCHAR) - `PENDING_HUMAN_APPROVAL`, `APPROVED`, `DISPATCHED`, `REJECTED`
  - `requested_by_user_id` (UUID FK)
  - `approved_by_user_id` (UUID NULLABLE)
  - `rejection_reason` (TEXT)
  - `dispatched_at`, `created_at`

### 2. Backend Implementation (`services/api/app/modules/expa/`)
- `models.py`: SQLAlchemy models for sync runs, staged records, reconciliation records, and gated mutations.
- `schemas.py`: Pydantic V2 schemas for sync runs, reconciliation actions, and mutation requests.
- `service.py`:
  - Ingestion adapter: handles mock/staging payloads simulating official GIS GraphQL/REST API or webhook events.
  - Conflict detection engine: compares staged EXPA state against local DB (`applications`, `opportunities`). Detects status mismatches (e.g. EXPA=`ACC` vs local=`SHORTLISTED`), unlinked records, and contract date discrepancies.
  - Reconciliation resolver: applies human operator resolution (`LOCAL_KEPT` leaves local operational state intact; `EXPA_ACCEPTED` updates local EXPA status without destroying operational readiness flags).
  - Outbound gated mutation handler: dispatches to EXPA only when explicitly approved by an authorized officer (`LCVP_ICX` or `LCP`).
- `router.py`: REST endpoints at `/api/v1/expa`:
  - `POST /api/v1/expa/sync/trigger`: Trigger polling ingestion run.
  - `POST /api/v1/expa/webhook`: Receive external webhook payload.
  - `GET /api/v1/expa/sync/runs`: List sync run history.
  - `GET /api/v1/expa/reconciliations`: List pending and resolved discrepancies.
  - `POST /api/v1/expa/reconciliations/{id}/resolve`: Resolve discrepancy.
  - `GET /api/v1/expa/mutations`: List outbound gated mutations.
  - `POST /api/v1/expa/mutations/{id}/approve`: Approve and dispatch mutation to EXPA.
  - `POST /api/v1/expa/mutations/{id}/reject`: Reject proposed mutation.

### 3. Frontend Implementation (`apps/web/`)
- `apps/web/src/lib/api/expa.ts`: Client for EXPA sync, reconciliation, and gated mutations.
- `apps/web/src/routes/(app)/expa/+page.svelte`: Data Reconciliation Console:
  - Sync status banner with "Trigger Manual Sync" button and last sync timestamp.
  - Discrepancy Matrix: Filter by Status Mismatch, Date Mismatch, Unlinked Records.
  - Visual Diff Viewer comparing Local Value vs EXPA Value side by side.
  - One-click resolution actions: "Keep Local Truth", "Adopt EXPA Status", or "Flag Conflict".
  - Outbound Mutations Queue: Tab showing pending mutations to EXPA with "Approve & Push" and "Reject" actions.
- App Navigation Update: Add `/expa` (EXPA Sync & Reconciliation) to Sidebar navigation.
