# 08-01-PLAN: Temporal Durable Workflow Engine, Activity Definitions & SLA Cascades

## Objective
Implement durable workflow orchestration for incoming exchange operational lifecycle, ensuring SLA timers (First Contact 24-48h, OP Review 72h, Pre-arrival checkpoints, Standards debriefs) survive process restarts, execute idempotently without duplicate notifications, and trigger escalation activities on breach.

## Proposed Changes

### 1. Database Schema (`database/migrations/008_temporal_and_expa_schema.sql`)
- `temporal_workflow_executions`:
  - `id` (UUID PK)
  - `workflow_id` (VARCHAR UNIQUE) - e.g. `wf-sla-contact-{app_id}`
  - `workflow_type` (VARCHAR) - `SLA_FIRST_CONTACT`, `SLA_OP_REVIEW`, `PRE_ARRIVAL_COUNTDOWN`, `STANDARDS_CHECKPOINT`
  - `entity_type` (VARCHAR) - `APPLICATION`, `EXCHANGE`
  - `entity_id` (UUID)
  - `status` (VARCHAR) - `RUNNING`, `COMPLETED`, `TIMED_OUT`, `FAILED`, `CANCELLED`
  - `input_payload` (JSONB)
  - `current_step` (VARCHAR)
  - `due_at` (TIMESTAMPTZ)
  - `started_at`, `completed_at`, `created_at`, `updated_at`
- `temporal_activity_logs`:
  - `id` (UUID PK)
  - `execution_id` (UUID FK -> `temporal_workflow_executions`)
  - `activity_name` (VARCHAR)
  - `idempotency_key` (VARCHAR UNIQUE)
  - `status` (VARCHAR) - `STARTED`, `SUCCESS`, `FAILED`
  - `retry_count` (INTEGER DEFAULT 0)
  - `result_payload` (JSONB)
  - `executed_at` (TIMESTAMPTZ)
- `operational_escalations`:
  - `id` (UUID PK)
  - `workflow_execution_id` (UUID FK)
  - `entity_type` (VARCHAR)
  - `entity_id` (UUID)
  - `severity` (VARCHAR) - `WARNING`, `CRITICAL`
  - `reason` (VARCHAR)
  - `escalated_to_role` (VARCHAR) - `LCVP_ICX`, `TEAM_LEADER`
  - `resolved` (BOOLEAN DEFAULT FALSE)
  - `created_at`, `resolved_at`

### 2. Backend Implementation (`services/api/app/modules/workflows/`)
- `models.py`: SQLAlchemy models for `TemporalWorkflowExecution`, `TemporalActivityLog`, and `OperationalEscalation`.
- `schemas.py`: Pydantic V2 schemas for workflow triggers, activity execution payloads, and SLA states.
- `activities.py`:
  - `activity_send_notification`: Idempotent activity checking `idempotency_key` before logging/dispatching notification.
  - `activity_escalate_sla_breach`: Marks entity readiness as `AT_RISK` and creates `OperationalEscalation` record for VP/TL.
  - `activity_evaluate_checklist_status`: Audits pre-arrival checklists (flight booked, visa approved, bed assigned).
  - `activity_trigger_standards_reminder`: Reminds EP & EP Manager of pending 16 mandatory/standards steps.
- `workflows.py`:
  - `WorkflowFirstContactSLA`: 48h SLA timer. If contact activity not recorded before due date, triggers escalation.
  - `WorkflowOPReviewSLA`: 72h SLA timer for OP screening feedback.
  - `WorkflowPreArrivalCountdown`: Cascading reminders at T-7 days, T-3 days, T-1 day before arrival date.
  - `WorkflowStandardsCheckpoint`: Day 1 welcome checkpoint, Week 2 evaluation checkpoint, Week 6 debrief.
- `service.py`: Durable workflow manager with support for external Temporal cluster connection as well as deterministic in-process resilient scheduler fallback for continuous offline operations.
- `router.py`: REST endpoints at `/api/v1/workflows`:
  - `POST /api/v1/workflows/sla/first-contact/{app_id}`
  - `POST /api/v1/workflows/sla/op-review/{app_id}`
  - `POST /api/v1/workflows/pre-arrival/{exchange_id}`
  - `GET /api/v1/workflows/executions`
  - `GET /api/v1/workflows/escalations`
  - `POST /api/v1/workflows/escalations/{id}/resolve`

  - Test idempotent activity execution (duplicate activity calls with identical idempotency key return cached result without duplicating alerts).
