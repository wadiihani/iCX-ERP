# Plan 05-02: Mandatory Closure Gates & Financial Proofs (T-13, DQ-071)

## 1. Context & Objectives
- **Phase**: M5 — Quality Cases & CS Minimums
- **Spec Reference**: `iCX_Data_Integrity_Tracking_Spec.md` §10.1 (Mandatory closure fields), §13.2 (DQ-071), §16 (Acceptance Test T-13).
- **Core Requirements**:
  1. **5 Mandatory Closure Fields (§10.1)**:
     - Case cannot close without:
       1. `description`
       2. `classification` (enum: `policy_breach`, `expectation_gap`, `other`)
       3. `resolution_steps` (ordered list with timestamps and actor attribution)
       4. `final_agreement_id` (signed/confirmed agreement reference)
       5. `financial_proof_id` (mandatory when `compensation_amount > 0` per DQ-071 / T-13)
  2. **Acceptance Test T-13 / DQ-071**:
     - Given case with compensation > 0 and no financial proof, when closing, then blocked.
  3. **Audit Attribution (INV-09)**:
     - All case closures emit `CLOSE_CASE` audit log with actor ID and before/after states.

---

## 2. Deliverables
- Implementation in `src/lib/data-integrity/quality-cases.ts` (`closeCase`).
- Acceptance tests verified in `tests/quality-cases-service.test.ts`.
