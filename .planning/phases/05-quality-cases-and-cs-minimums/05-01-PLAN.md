# Plan 05-01: Quality Cases Schema & CS Minimums Data Layer

## 1. Context & Objectives
- **Phase**: M5 — Quality Cases & CS Minimums
- **Spec Reference**: `iCX_Data_Integrity_Tracking_Spec.md` §10 (Module E — Quality cases & compensation, S4), §12.1 (INV-03), §13.2 (DQ-071), §16 (Acceptance Test T-13).
- **Core Requirements**:
  1. **Quality Cases Schema (`case_quality`)**:
     - `id`: UUID PK
     - `exchange_id`: UUID FK -> `exchange(id)`
     - `title`, `description`
     - `classification`: enum (`policy_breach`, `expectation_gap`, `other`)
     - `opened_at`, `first_response_at`, `closed_at`
     - `resolution_steps`: ordered list with timestamps
     - `compensation_amount`: numeric default 0
     - `currency`: default 'MAD'
     - `compensation_type`: enum (`refund`, `reimbursement`, `migration_fine`, `goodwill`, `other`) per S9 migration fines
     - `financial_proof_id`: UUID / text (proof reference)
     - `final_agreement_id`: text (signed/confirmed agreement reference)
     - `recurrence_of`: UUID FK -> `case_quality(id)` (links earlier recurring case)
     - `owner_id`: UUID FK -> `member(id)` (mandatory active owner INV-03)
  2. **CS Minimum 1 (Centralised Handling & Response Time Tracking)**:
     - No case exists outside the tool.
     - `recordFirstResponse(caseId, actorId, responseNotes)` calculates response time (`first_response_at - opened_at`) and logs communication.
  3. **CS Minimum 2 (EP & Exchange Tracking Dossier)**:
     - Comprehensive dossier joining `exchange`, `ep`, `opportunity`, `case_quality`, `status_request`, and `compensation` breakdown.
  4. **System Invariants**:
     - INV-01: Prohibit hard deletes on `case_quality`.
     - INV-03: Mandatory active owner.
     - INV-09: Universal audit logging on all mutations.
